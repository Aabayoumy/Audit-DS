## What this project is

**Audit-DS** is a PowerShell module (`AuditModule`) for auditing Active Directory environments. It targets PowerShell 5.1+ and must run as Administrator on a domain-joined Windows machine with RSAT tools installed.

## Build

Run from the repo root in PowerShell (on Windows):

```powershell
.\_build.ps1
```

The build script concatenates every `.ps1` in `AuditModule/public/` and `AuditModule/private/` (sorted by name) into `Audit-DS.ps1` at the repo root. This file is the single-script distribution artifact — users who don't want to import a module can run it directly.

## Load and test the module locally

```powershell
# Run as Administrator from repo root
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser -Force
Import-Module -Name .\AuditModule -Force
Get-Command -Module AuditModule
```

## Module architecture

```
AuditModule/
  AuditModule.psm1      # Entry point: dot-sources all private then public .ps1 files
  AuditModule.psd1      # Manifest: version, GUID, FunctionsToExport list
  public/
    00-Variables.ps1    # Sets $Global:DomainName, $Global:OutputPath (c:\<domain>), $Global:PingCastleTag
    Export-*.ps1        # One exported function per file
    Get-*.ps1
    Install-*.ps1
    Start-*.ps1
    Enable-*.ps1
    New-*.ps1
  private/
    _*.ps1              # Internal helpers, not exported
```

**Load order matters:** `AuditModule.psm1` dot-sources `private/` first, then `public/`. `00-Variables.ps1` (sorted first alphabetically) runs before other public functions and sets globals that all functions depend on.

**Global variables** set in `00-Variables.ps1` and used everywhere:
- `$Global:DomainName` — current AD domain short name
- `$Global:OutputPath` — root output directory, defaults to `C:\<DomainName>`
- `$Global:PingCastleTag` — PingCastle version to download (e.g. `3.5.0.44`)

**Output layout:** All functions write to `$Global:OutputPath\<yyyy-MM-dd>\<FunctionFolder>` (e.g. `C:\corp\2025-08-26\ADInfo\`).

## Key private helpers

| File | Purpose |
|------|---------|
| `_AssertAdminPrivileges.ps1` | Throws if not running as Administrator — called at the top of most public functions |
| `_Create-HTMLReport.ps1` | `Export-Report` function: pipeline-based HTML report builder with TOC |
| `_MapGuidsToGpoNames.ps1` | Resolves GPO GUIDs to display names |
| `_UserSecurityHelpers.ps1` | ACL parsing and SDDL comparison helpers for `Export-UserSecurity` |
| `_Import-GPOs.ps1` | Internal GPO import logic used by `Enable-Audit` |

## Adding a new exported function

1. Create `AuditModule/public/<Verb>-<Name>.ps1` with the function definition.
2. Add the function name to `FunctionsToExport` in `AuditModule.psd1`.
3. Add the function name to `Export-ModuleMember -Function` in `AuditModule.psm1`.
4. Run `_build.ps1` to regenerate `Audit-DS.ps1`.

## Versioning and releases

- Version is set in `AuditModule.psd1` → `ModuleVersion`.
- Release zips are named `AuditModule-v<version>.zip` and `Audit-DS-Script-v<version>.zip` — these are build artifacts committed to the repo, not generated by the current build script (the zip section in `_build.ps1` is commented out).
- Releases are published to GitHub: `https://github.com/Aabayoumy/Audit-DS/releases`.

## Quick-launch `.cmd` files

`Run-LDAPExport.cmd` and `Run-NTLMExport.cmd` are convenience wrappers that open a new elevated PowerShell window, bypass execution policy for the process, import the module manifest directly, and run the target export function. Use these as the pattern for any new `.cmd` launcher.
